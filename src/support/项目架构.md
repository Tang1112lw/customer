本项目以 Windows 0.4.7 的 `AICRM-Key.exe`（取密钥、列本地账号）与 `AICRM-Export.exe`（导出 `messages.json` 给云端流水线）为辅助程序，另有 `aicrm-export-new.exe` 产出给人看的 `messages.md`（不在仓库里，由 `install.ps1 -ExportProgram` 指定）。Rust 服务在 `backend/service/` 调用进程并处理文件：`service/mod.rs` 为共享底座（`Service` 状态、辅助程序调用、并发闸门、`authorize` 中间件），`service/key_service.rs` 承载密钥业务，`service/export_service.rs` 承载 Markdown 导出与打包（NDJSON / ZIP / AI ZIP），`service/archive_service.rs` 承载 `AICRM-Export.exe` 导出 + 归档包合并 + 上传云端，`service/agent_service.rs` 是云端命令通道（长轮询 + 心跳）；`backend/tools_api.rs` 只注册 HTTP 路径。

`backend/mod.rs` 的 `app()` 负责组装全部模块并在顶层统一上锁：`merge` 各模块的 `Router<Arc<Service>>` 之后调一次 `route_layer(middleware::from_fn_with_state(service, authorize))`，再 `with_state(service)`。因此新增模块无需实现鉴权，也无需改 `main.rs`。`GET /api/aicrm/session` 刻意挂在这一层之外 —— 它存在的意义就是让浏览器前端先拿到令牌 —— 改由 `Origin` 白名单把关，白名单来自环境变量 `AICRM_ALLOWED_ORIGINS` 与可重复的 `--allow-origin`。CORS 中间件包在最外层，预检 `OPTIONS` 由它直接回 204，不进鉴权层。`main.rs` 做参数解析、注入来源白名单、在设备凭据齐全时 `agent_service::spawn` 起云端命令通道，最后 `axum::serve(listener, app(service))`。

当前已实现登录自启、Bearer 鉴权、版本/帮助/账号查询、密钥准备、按联系人和日期导出、原始 NDJSON、原始 ZIP、AI ZIP、数据采集（导出 + 归档上传，`POST /api/aicrm/collect`）、云端命令通道（`wechat.bind` / `wechat.export` / `wechat.collect`）、系统托盘与图形一键安装。详细用法与真实接口测试见项目根目录 `README.md`。

## 登录窗口（`src/forckend/`）

`Cargo.toml` 声明四个二进制：`aicrm_windows_api`（后台服务，无界面，`src/main.rs`）、`aicrm-login`（登录窗口，`src/forckend/main.rs`）、`aicrm-tray`（系统托盘，`src/forckend/tray.rs`）、`aicrm-setup`（图形一键安装，`src/forckend/setup.rs`）。它们不共享模块 —— 各自按需自带 `cloud.rs`（云端协议）与 `store.rs`（设备标识、令牌落盘），这样服务侧不必链接 GUI 依赖。

令牌链路的完整形态：

```
用户输入账号密码 → aicrm-login 走 HTTPS POST 到云端 `/api/auth/login`（默认 `http://127.0.0.1:8000/api/auth/login`，正式环境必须 HTTPS）
                 → 云端校验密码、签发会话令牌
                 → aicrm-login 把令牌写进 %LOCALAPPDATA%\AICRM-Windows-API\api.token
                 → 后台服务读该文件做 Bearer 鉴权
                 → 云端调用本地 API 时用自己签发的同一个令牌
```

关键设计取舍：

- **登录请求不带 `Authorization`**。它是"用凭据换令牌"的入口，不可能要求令牌；因此它是公开端点，只能靠 HTTPS + 云端失败次数限制防滥用。客户端 `transport_warning()` 会在非 HTTPS 且非本机地址时常驻红字提示。
- **密码不在本地校验**，只在内存里活到请求发出为止（`std::mem::take` 后 move 进线程）。本地校验等于在客户端藏一份密码哈希。
- **令牌由云端签发，因此无需任何人工交付**。云端把令牌与 `device_id` 一起入库，即可单独撤销某台设备。
- 登录调用跑在独立线程（`std::thread::spawn` + `mpsc`），完成后用 `ctx.request_repaint()` 唤醒 UI；这是 egui 的标准异步回填方式。
- egui 自带字体不含 CJK，`install_cjk_font()` 按 `msyh.ttc → simhei.ttf → Deng.ttf → simsun.ttc` 顺序加载系统字体，否则整个界面是方框。
