# 项目架构

（2026-10-10 第二次重构后更新：**设备层整体删除**。二进制清单、用法与接口契约以
`README.md` 为准，本文只讲结构。）

## 总原则：账号即客户端

**没有「设备」这个东西。** 云端只认一件事：客户端有没有用某个账号登录着。
配对、设备令牌、预置码、设备归属全部删除 —— 云端迁移 `004_account_client.sql`
删掉了 `aicrm_agent_devices` / `aicrm_agent_device_sessions`，命令改为按 `user_id`
投递（`aicrm_agent_clients`：一个账号一行）。**一个账号只能登录一个客户端**：
第二台电脑登录时若第一台仍在线则心跳被拒（409），第一台离线超过 2 分钟后自动接管。

## 五个二进制，共享 `src/shared/` 的无界面工具

- `src/main.rs` —— `aicrm_windows_api`（后台服务，无界面）：HTTP 接口（axum，
  127.0.0.1:8765）+ 云端命令通道。**零参数启动**：默认从 exe 同目录读
  `tools/`、`accounts/`、`data/`、`api.token`、`api.refresh`、`cloud.url`、`client.id`。
- `src/forckend/console.rs` —— `aicrm-console`（主窗口 + 托盘 + 登录）：状态总览 /
  配置页 / 账号菜单；托管本地服务；未登录时首屏是「连接云端」登录页。
- `src/forckend/setup.rs` —— `aicrm-setup`（安装器）：**先做环境准备**（清单 + 门禁），
  通过后读自身末尾页脚解出载荷 → 跑 `install.ps1` 落盘 → 拉起客户端 → 自删。
  支持 `--check`（无界面环境检查）与 `--extract-only`（自检）。
  **只走有界面一条路**：先直接开窗口，开不出来才带随包 Mesa 重启一次（见「渲染」一节，
  2026-10-16 改惰性），任何机器都开得出窗口；重启后仍失败即报错退出（退出码 1）并写日志，
  不静默降级（2026-10-15 用户明确要求：必须使用 OpenGL）。
  安装全程持界面单实例锁（2026-10-15 修：曾开装即放锁，重复双击会并发跑两个 install.ps1）；
  带 Mesa 重启前必须放锁（2026-10-16 修：否则子进程被"已有实例"挡掉）。
- `src/update/main.rs` —— `aicrm-update`（原生更新器）：宽限期 → 复算摘要 → 停客户端
  进程 → 备份 → 覆盖 → 重启 → 清理 → 刷新快捷方式 → 探活/回滚。
- `src/pack/main.rs` —— `aicrm-pack`（打包工具，不随包分发）：安装器 + 载荷拼成单文件。

## 共享层（src/shared/）

跨二进制的无界面工具，**文件之间零交叉引用**（每个文件都可单独按需引入）：

| 文件 | 职责 | 使用方 |
| --- | --- | --- |
| `paths.rs` | 安装目录与文件位置的唯一约定（含 `client.id`） | 主控台 / 安装器 / 更新器 |
| `credentials.rs` | 登录凭据（令牌 / 刷新令牌 / 账号名）落盘 + icacls 收紧 | 主控台 |
| `session.rs` | 令牌"是否未过期"判定（本地解 `exp`，不联网） | 服务端 + 主控台 |
| `dialog.rs` | 失败可见：原生 `MessageBoxW` 提示 + 追加式错误日志 + panic 兜底 | 主控台 / 安装器 |
| `preflight.rs` | 解析 `install.ps1 -CheckOnly` 的 `CHECK|...` 清单 | 安装器 |
| `process.rs` | 杀进程名单与终止 / 探测 | 主控台 / 更新器 |
| `cache.rs` | 解密缓存探测（密钥"真的能用"与否） | 服务端 / 主控台 |
| `self_name.rs` | 从导出目录提取机主昵称 | 服务端 / 主控台 |
| `font.rs` | egui 中文字体（单独引入，不把 GUI 依赖带进服务） | 主控台 / 安装器 |
| `sha256.rs` | 无依赖摘要（单独引入） | 服务端 / 更新器 |
| `base64.rs` | 无依赖 Base64 编码（单独引入）：归档里的语音媒体要靠它塞进 JSON | 服务端 |

## 令牌链路

```text
主控台「连接云端」→ HTTPS POST 云端 /api/auth/login（密码只经云端校验）
                   body 带 client_id（本机实例标识）
  → 写 account.name / api.token（icacls 收紧）/ api.refresh → 重启服务即生效
服务每 20 秒心跳：Authorization: Bearer <api.token> + X-AICRM-Client-ID: <client.id>
  → 云端登记「这个账号的客户端在线」；网页端同账号即可绑定微信 / 下发采集
服务每 30 分钟用 api.refresh 续期写回；令牌过期 = 未登录，界面引导重新登录
```

## 安装前的环境准备

`install.ps1` 的第一个动作就是检查（并在 `-CheckOnly` 时只检查、不动磁盘）：
系统版本（≥ Win10 1809 / 内部版本 17763）、磁盘空间（≥300MB）、安装目录可写、
**VC++ 运行库来源**（必须项），以及开机自启、云端连通性、微信是否安装（提醒项）。
输出协议是一行一条 `CHECK|级别|标题|pass/fail|说明`（级别 `required` 不通过就拦、
`advisory` 只提醒），安装器界面据此画清单：必须项全过才放行「开始安装」。

**开机自启是提醒项，且有两级落点**（2026-10-12 下午改）：先试 `HKCU\...\Run`，写不进就退到
**启动文件夹快捷方式**（`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\`）。
客户机上「启动项可写」失败很常见（安全软件锁启动项 / 域策略 / 受限账户），而它只影响
「开机自动起来」—— 客户手动双击桌面图标照样能用，不该因此把整台机器拦在安装之外。
收尾如实报告自启落在哪里，不假装成功。

**客户机不需要预装 VC++**：我们自己的程序静态链接 CRT（`.cargo/config.toml`），
第三方程序（`AICRM-Key.exe` / `aicrm-export-new.exe`）靠随包携带 `vcruntime140.dll`
到 `tools\` 与安装目录（应用本地装配，免管理员 / 免联网 / 免重启）。

## 绑定微信 = 真抓（0.1.48）

网页点「绑定微信账号」= 让那台电脑重新抓一次密钥。三层"复用"要一起看：

1. **客户端包装层**（`backend/service/key_service.rs::prepare`）：**不复用**，
   只保留服务每 10 分钟自检用的 `no_restart`（那条不能重启客户微信）；
2. **抓密钥程序 `AICRM-Key.exe`**：它自己会"验证通过就复用、不重启微信"——
   用 `--force` 压过（手册原文：忽略已有密钥并重新捕获）；
3. **云端**（`control-plane/store.go::CreateBinding`）：绑定指令一律 `force: true`。

结果：点一次绑定必定真抓（微信重启、需重新登录）；抓不到就报真实原因，不会拿旧密钥冒充成功。

**微信程序路径由客户端自己找**（`src/shared/wechat.rs`，走 `windows-sys` 的
`Win32_System_Registry`）：注册表安装登记 → 常见安装目录；找到就传 `--weixin-exe`，
找不到把工具那句"请用 --weixin-exe 指定"翻成可照做的中文提示（`translate_key_error`）。

## 版本发布与自更新（0.1.48 实测）

```bash
cd windows/control-plane
go run ./cmd/publish-program -kind agent   -version 0.1.48 -file agent-0.1.48.exe
go run ./cmd/publish-program -kind console -version 0.1.48 -file console-0.1.48.exe
sudo systemctl restart aicrm-control-plane   # programs.json 启动时读入
```

**老客户端升不动的坑**：0.1.47 及更早讲的是设备令牌协议，与新云端不兼容（401），
**收不到更新命令** → 必须用新安装包覆盖一次；覆盖之后自动更新可用（已实测 0.1.47→0.1.48）。

## 渲染：为什么随包带一份软件 OpenGL（2026-10-12 下午）

两个窗口都是 eframe / egui（`glow` 后端），**要求 OpenGL 2.0+**。而客户机只给 1.1 的情况
很常见 —— 不是显卡差，而是**「远程桌面」会把 OpenGL 强制降到 1.1**（与驱动无关），
或者显卡驱动没装全（Windows 只提供 1.1 的软件实现）。窗口在**创建阶段**就失败，
表现就是"双击没反应 / 窗口打不开"。

兜底：随包带一份 Mesa 的 llvmpipe（`src/tools/swgl/`，5 个 DLL），由 `install.ps1` 铺进
**安装目录**（也就是 `aicrm-console.exe` 旁边，应用本地装配），Windows 会优先用它们 ——
渲染搬到 CPU，任何机器都开得出窗口。`console.rs` 启动时还必须同时置
`GALLIUM_DRIVER=llvmpipe` 与 `LIBGL_ALWAYS_SOFTWARE=1`：少了这两条，Mesa 会去找硬件驱动
并直接失败（实测：进程秒退、无任何日志）。

代价是所有机器都走软件渲染（这个状态窗口只在画面变化时重绘，基本无感）；`libgallium_wgl.dll`
一个文件 61.8MB，安装包因此从 47.8MB 涨到 71.9MB。

**安装器自己怎么办**（2026-10-15 补，客户实测「安装程序启动失败」后）：它是单文件 GUI，
旁挂 DLL 到不了它，opengl32.dll 又是编译期导入表依赖（进程一启动就按「应用目录优先」
解析，运行期 SetDllDirectory 来不及）。做法：启动时先直接开窗口，开不出来才把载荷里的
5 个 DLL 和**自身副本**落进同一个临时目录、从副本重启（2026-10-16 改为惰性：硬件 GL
完好的机器白付一次上百兆复制与重启没有意义）—— loader 于是优先加载 Mesa，安装窗口在
1.1 机器上也能开。重启后仍开不出窗口的，报错退出（退出码 1）并写日志
（`install.err.log`），不静默降级 —— 客户看不到安装过程比装不上更糟。
**重启前必须放掉单实例锁**：`run()` 失败前已经拿过锁，不还回去子进程会被"已有实例"
挡掉（2026-10-16 修，正是以前"装完了客户端弹不起来"那个坑）。

**staging 收尾**（2026-10-16）：装完删的是客户原本双击的那个安装包（父进程经
`AICRM_SETUP_ORIGIN` 把原始路径透传给子进程；临时副本由父进程连 staging 目录一起收走）；
`aicrm-swgl-*` 纳入陈旧临时目录清理（父进程被强杀会留下一百多兆，见
`remove_stale_payload_dirs`，自己的 staging 目录经 `AICRM_SWGL_STAGE` 识别并避开）；
就位失败写 `install.err.log`（「软件 OpenGL 就位失败」）；`--check` / `--extract-only`
不建窗口，跳过 staging。

## 界面约定

- 两个窗口（主控台 / 安装器）共享 `theme.rs`（浅色底、白卡片、描边、留白），各自
  `mod theme;` 指向同一份文件，不引入共享库。
- 单实例：主控台与安装器共用命名互斥体 `Local\AICRM.WinClient`。**抢不到锁时安装器
  会明确提示**（"已有 AICRM 在运行，请先从托盘退出再装"），不再静默退出 ——
  以前那看起来就是"双击安装程序没反应"。
- 主控台不依赖服务：状态全部直接读安装目录里的文件（它的职责之一就是在服务没跑时
  把服务拉起来）。
- egui 自带字体不含 CJK，`shared/font.rs` 按 `msyh → simhei → Deng → simsun` 顺序
  加载系统字体，否则整个界面是方框。
